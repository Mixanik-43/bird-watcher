# bird-watcher

Две практические работы для человека, знакомого с Python и классическим ML:
свой модуль на PyTorch и дообучение vision-language модели через LoRA.

**Статус:** реализация и проверка эталона в процессе. Результаты проверки находятся
в `reports/validation.md`; наличие кода не означает, что GPU-обучение уже проверено.

## Данные

Используем CUB-200-2011, восемь классов: Gadwall, European Goldfinch, Mallard,
Common Raven, House Sparrow, Bank Swallow, Barn Swallow, Bohemian Waxwing.
Это пересечение CUB с евразийскими птицами, а не полный справочник московского парка.
Не заменяем American Crow на серую ворону, Tree Sparrow на полевого воробья и
североамериканские виды на похожие европейские.

В CUB около 60 фотографий на вид: наш набор заметно меньше первоначально обсуждавшихся
1500–2400 фотографий. Официальный test сохраняется; из официального train выделяется
20% validation. Все вопросы об одной фотографии остаются в одной части.

Вторая работа использует **атрибуты изображений**, а не средние атрибуты видов.
В исходной разметке есть `is_present` и `certainty_id`. Берём уверенность 3/4,
противоречивые ответы исключаем. `not visible` и `guessing` не считаем ответом «нет».
Цвета не взаимоисключающие: у крыла могут быть несколько цветов. Поэтому первое VQA —
короткие бинарные вопросы о форме клюва, цвете груди и крыльях, с ответами yes/no.
Разметка видимости частей существует отдельно; ответы о невидимости пока не обучаем.

Изображения не включены в GitHub. Загрузчик скачивает официальный архив и проверяет MD5.
Авторы ограничивают использование изображений некоммерческими исследованиями и образованием;
MIT в этом репозитории относится только к нашему коду. CUB может пересекаться с ImageNet:
это учебная проверка адаптации, не доказательство отсутствия данных в предобучении.

Источник: https://www.vision.caltech.edu/datasets/cub_200_2011/
Архив: https://data.caltech.edu/records/65de6-vp158

## Запуск

В Python 3.12, из корня репозитория, с уже подходящим PyTorch:

```bash
pip install -e '.[dev,vlm]'
python scripts/prepare_data.py
pytest -q
python scripts/train_resnet.py
python scripts/train_vlm.py --steps 100
```

Для локальных упражнений без VLM достаточно `pip install -e '.[dev]'`.
В Kaggle: включить Internet и GPU T4 x2. Учебный код использует одну карту;
скрипт запускайте с `CUDA_VISIBLE_DEVICES=0`, чтобы Trainer не включал DataParallel.
Вторая карта не добавляет памяти первой. Ноутбук `notebooks/00_kaggle_validation.ipynb`
готовит среду и запускает эталон. На T4 используется FP32 для устойчивого базового пути;
на GPU с BF16 — BF16. Оптимизацию и другие kernels добавляем после рабочего baseline.

Если Caltech возвращает HTTP 403 из Kaggle, подготовьте набор локально, упакуйте
**содержимое** `data/cub8` в ZIP и добавьте как приватный Dataset через File → Upload input.
В проверочном ноутбуке есть загрузка подключённого `manifest.jsonl`. Нужен только один
подключённый набор с таким manifest. Это не требует соревнования или публичной публикации.

В проверенном образе Kaggle предустановлен `torchao 0.10`, несовместимый с PEFT 0.20.
Проверочный ноутбук удаляет его из временной Kaggle-среды: квантизацию мы не используем.
Локальное окружение эта ячейка не должна менять; она предназначена только для Kaggle.

## Учебный маршрут

- `notebooks/01_resnet.ipynb`: `nn.Module`, forward, заморозка, BatchNorm,
  градиенты, обучение головы и последнего блока, сохранение модели.
- `notebooks/02_vlm.ipynb`: собственный LoRA-слой, его градиенты и слияние,
  tokenizer/processor, chat template, маска loss, обучение PEFT-адаптера,
  генерация и проверка использования изображения.
- `solutions/`: те же ноутбуки с решениями. Они генерируются из одного источника
  `scripts/build_notebooks.py`, чтобы задания и ответы не расходились.

Результат VLM сравнивается с исходной моделью и простым ответом по большинству для
каждого вопроса. Корректный формат ответа сам по себе не означает распознавание.
Учебные assertions проверяют механику; качество нужно измерять, а не угадывать порог.

## Свои фотографии

Для первой работы можно использовать обычный `torchvision.datasets.ImageFolder`:
`train/<вид>/*.jpg`, `val/<вид>/*.jpg`, `test/<вид>/*.jpg`. Сохраните единое соответствие
номеров классов между частями. Соседние кадры одного визита птицы группируйте вместе.
Для VQA добавляйте проверенные атрибуты в manifest; отсутствие аннотации означает
пропуск вопроса, а не отрицательную метку. Модель пока рассчитана на фото одной птицы,
а не на автоматическое обнаружение птиц в произвольном кадре фотоловушки.

Бонус: найдите похожие снимки по DINO/CLIP embeddings и покажите соседей. Не удаляйте
пары автоматически: близость признаков не доказывает дублирование.
